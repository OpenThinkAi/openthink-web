pm keeps tickets and projects in a local SQLite database, and every change is an op in an append-only log. One binary is both the human CLI and the agent contract — no prompts, --json on every read, stable exit codes.

// how it works

The log is the database. Tables are derived from the op log, and pm doctor checks they replay from it. Fields merge last-writer-wins, labels as sets, and descriptions are Loro text CRDTs, so concurrent edits merge instead of clobbering.

Built to be scripted. Nothing reads stdin or prompts. Every read takes --json and returns a versioned {"schema": 1, …} shape. Exit codes: 0 ok, 1 error, 2 usage, 3 not found, 75 taken.

Ready means ready. pm ready lists unstarted, unassigned, unheld, ungated tickets whose blockers are done. pm hold hands one to a human; pm check reports stale tickets, holds and blocker cycles.

Sync is optional. Alone, the local database decides. With a self-hosted pm-hub, pm sync pushes and pulls ops, the hub assigns ticket numbers, and claims are decided first-come, so two machines can't take the same ticket.

A board when you want one. pm app opens the board in ui-leaf; pm edit opens the ticket editor, or $EDITOR when there's no display.

It doesn't dispatch, assign or run pipelines. It stores ticket state; a build loop calls pm the way it calls git.

// try it

$ pm init
$ pm new --title "Write the release notes"
$ pm claim --ready
$ pm done PM-1

Moving from a markdown vault? pm import vault <path>. Every verb, flag and --json shape is in the CLI contract; the rest is in the README.
